# AGENTS.md

## What this is

Headless HDMI capture appliance (C++26 + GStreamer): grabs 1080p60 video from a
V4L2 device and outputs it via DRM/KMS. Implemented: the low-latency
passthrough plus a pink no-signal fallback (when the capture side stops, the
frame buffer is kept stocked with generated pink frames and output keeps
running), the MJPEG preview from #376 (`--web` serves `/api/preview.jpg` and
`/api/preview.mjpeg` on port 8080), the SRT subtitle overlay from #438
(`--subtitles=<file>`, plus boot resume of the state dir's `active` marker),
the subtitle upload endpoint from #212 (`PUT /api/subtitles/<title>`
stores into the library, marks it active, and switches it in live;
`GET /api/subtitles/<title>` answers the stored SRT as `{"body":...}`
JSON), and
the subtitle control endpoints from #441 (`GET /api/subtitles` lists the
library; `GET`/`PUT /api/subtitle-state` reads/changes the file,
visibility, pause, position, delay, and cue font (family, size, color) — `docs/rest-api.md` is
the reference; unmatched routes fall back to static files from the web
root), `GET /api/fonts`, which lists the renderer-available font
families (#159), and `GET /api/opensubtitles`, which answers the
`--api-key` value as JSON. Also implemented: the whisper tap from #19 —
English-only whisper.cpp transcription of the capture audio, logged
(`--whisper=<model>`, or toggled live with model selection and
browser-driven download via `GET`/`PUT /api/whisper` and
`PUT /api/whisper/models/<name>`; `[whisper] enabled`/`model` persist
in the config), and the one-shot auto-sync from #433 (`PUT
/api/subtitle-sync` listens to the audio, matches the transcript
against the attached SRT, and jumps the SRT clock to the matched
position; the web UI has the "Auto Sync" button). Also implemented: the persistent
configuration from #16 (INI via GLib GKeyFile, versioned format #232;
every command-line option plus the web-API subtitle style state —
file, visibility, delay, cue font family/size/color, #222–#224 —
validated at load with per-key recovery #219/#220, written back
atomically #221; `config/subtitler.example.ini` documents the keys).
Also implemented: the systemd unit from #431
(`config/subtitler.service` — runs `subtitler --web` as the
`subtitler` user with XDG config/state pointed at `/etc/subtitler`
and `/var/lib/subtitler` via ConfigurationDirectory/StateDirectory,
`Restart=on-failure` with no start rate limit so a late-enumerating
CV105 never strands the appliance; output-bus failures now exit the
process, #447, so systemd restarts cover runtime output death too) and
the Debian packaging (`debian/`, debhelper: dh_installsystemd
enables+starts the unit, systemd-sysusers creates the service user,
`dpkg-buildpackage` wrapped by the CMake `deb` target). Planned but
NOT yet implemented: the #15 web interface proper (static assets in
`web/` — `index.html` + `assets/style.css`, growing piecemeal).

## Threat model

The only supported deployment is a **trusted LAN**. The web server
(port 8080) listens on all interfaces with no authentication or TLS,
all state-changing endpoints are unauthenticated, and
`GET /api/opensubtitles` serves the configured OpenSubtitles API key
to anyone who can reach the port. These are deliberate appliance
trade-offs, not oversights; if the deployment ever changes, revisit
binding and authentication before exposing the port.

Consequently the HTTP-input hardening work is **chores, not pressing
security fixes**: #445 (pipeline-syntax injection), #446 (unbounded
numeric REST inputs), and #448 (transactional subtitle activation).
Suggested order: #446 first (cheapest), then #445 and #448 together
(both restructure `StartOutput`'s construction/teardown ordering).
Per-issue triage notes live in comments on the issues.

## Build

```sh
cmake --preset default
cmake --build --preset default
```

- The `default` preset in `CMakePresets.json` sets the Ninja generator, `build/` binary dir, and clang++ — the README, the VSCode task, and manual builds all go through it.
- If `build/` already exists configured with Makefiles, delete it first — CMake errors on generator mismatch instead of switching in place.
- Requires CMake >= 3.30 and a very recent C++26 compiler (uses `std::print`, `std::format`, `std::out_ptr`, `std::jthread`). Verified with Clang 22.1.8 (dev machine) and clang 19 on the Pi 5 target (trixie; see `docs/pi-setup.md`).
- Dependencies resolve via pkg-config (all `REQUIRED`; configure fails if dev packages are missing): gstreamer-1.0, gstreamer-app-1.0, gstreamer-audio-1.0, gstreamer-video-1.0, glib-2.0 / gobject-2.0 / gio-2.0, libsoup-3.0, pangocairo (the stream lib's font enumeration, #159), libdrm (`subtitler-probe` only) and alsa (probe plus the stream lib's audio-output probing). Tests additionally use doctest via `find_package(doctest REQUIRED)` (CMake package, not pkg-config). The one non-pkg-config dependency is whisper.cpp (#19): `SUBTITLER_ENABLE_WHISPER` (default ON) fetches whisper.cpp v1.9.3 with FetchContent and links the stream lib against it — the first configure of a build dir clones it, so it needs network. OFF is for offline/minimal builds: the tap module compiles to a stub and `--whisper` just fails model loading. FetchContent pins `WHISPER_BUILD_TESTS`/`WHISPER_BUILD_EXAMPLES`/`BUILD_SHARED_LIBS` off via CACHE FORCE — whisper.cpp's own `cmake_minimum_required` resets CMP0077 to OLD in its scope, so plain variables would be ignored — and declares the subdirectory `EXCLUDE_FROM_ALL`, because v1.9.3's install rules are unconditional and would otherwise leak its static libs, headers, and cmake/pkgconfig files into `cmake --install` (and the deb).
- Tests run with `ctest --test-dir build` (doctest unit tests under `tests/`, registered via `doctest_discover_tests`; gated on `BUILD_TESTING`, default ON). The description tests parse real pipelines with `gst_parse_launch`, so the machine running the suite needs the GStreamer runtime plugins (v4l2src, appsink/appsrc, kmssink) installed, not just the dev packages; the audio-branch constructibility check additionally uses alsasrc but skips when it is absent. The throughput test (`tests/integration_tests.cpp`) runs a real `Stream` for ~8 s against the capture device (default `/dev/video0`, override with `SUBTITLER_TEST_VIDEO_DEVICE`) with the audio output on the ALSA `null` PCM device — it guards the shared-timeline and latency-recalculation path (#128, #437) and skips when no usable CV105 is present; the `null` device works only for playback, never as a capture source (it is not rate-limited and poisons the capture pipeline's clock). The whisper tests (`tests/whisper_tests.cpp`, built only with `SUBTITLER_ENABLE_WHISPER`) run real inference when `SUBTITLER_TEST_WHISPER_MODEL` names a ggml model (e.g. ggml-tiny.en.bin) and `SUBTITLER_TEST_WHISPER_WAV` a 16 kHz mono S16 WAV (whisper.cpp's `samples/jfk.wav`), and skip otherwise. No CI, no CMake lint targets. Verification = a clean `cmake --build build` plus passing ctest.
- Formatting: clang-format with the repo's `.clang-format` (Google base, 2-space indent, 80 columns) for C++; Prettier + ESLint for `web/` (JS/HTML). The web tooling lives at the repo root — `package.json` (devDependencies only; keep it out of `web/`, which `install(DIRECTORY web ...)` ships verbatim), `.prettierrc.json` (80 columns, 2-space, matching .clang-format), and `eslint.config.js` (flat config: `eslint:recommended` + browser globals for `web/**/*.mjs`, `eslint-plugin-html` for the inline module in `index.html`). Run `npm run format` / `npm run lint` / `npm run check`; `npm install` is needed once per checkout. `.vscode/settings.json` wires format-on-save (Prettier) and fix-on-save (ESLint) for javascript/html/css only — C++ stays on clang-format.

## Layout and conventions

- Naming follows the Google C++ Style Guide: types and functions are `CamelCase`, constants are `kCamelCase`, variables are `snake_case` with a trailing `_` on class data members. snake_case is kept only where a name deliberately mirrors an external API (the `gst_unref` overloads in `deleters.h`, `Fd::get`/`release`/`reset`, `ResetGuard::release`).
- All headers are private and live next to their sources under `src/`. The include root is `src/`, so includes look like `#include "stream/stream.h"`. The root `include/` directory is intentionally empty, reserved for a future public API — do not put headers there.
- `src/config/` builds the static lib `config` (alias `subtitler::config`): the persistent INI configuration (#16) via GLib GKeyFile. `Config::Load` parses and validates (#219/#220) — a missing file is an empty writable document, a malformed one or an unsupported `[subtitler] version` (#232) is refused wholesale and never clobbered, and individual bad keys are dropped with a log warning; empty values count as unset. The setters write back the web-API subtitle style state, the `[whisper] enabled`/`model` state, and the explicitly command-line-supplied `[capture] device` and `[web]` keys (video-device/`--web`/`--web-root`/`--api-key`), and `Save()` persists atomically (temp file + rename, #221), preserving comments and unknown keys. Consumed only by `src/main.cpp`, which merges it under the command line and re-applies the persisted style whenever subtitles attach (a file switch resets the delay). At startup the attached subtitle resolves in the precedence order `--subtitles` → `[subtitles] file` → the `active` marker; a restored path naming a library entry reports its title to the state endpoint (`docs/rest-api.md`), a path outside the library reports `file: null`.
- `src/stream/` builds the static lib `stream` (alias `subtitler::stream`), consumed only by the `subtitler` executable from `src/main.cpp`. New modules should follow the same `src/<module>/` pattern with their own CMakeLists.
- `src/probe/` builds the `subtitler-probe` diagnostic executable (#94): capability probes via native APIs (GStreamer registry, V4L2 ioctls, libdrm, ALSA), a pipeline recommendation/negotiation check, text and `--json` output. Probe is standalone and contained: it may include from `utils/` and `stream/`, but nothing outside `src/probe/` includes from it.
- `src/web/` builds the static lib `web` (alias `subtitler::web`): the appliance web server (libsoup 3). `WebServer` (`web_server.{h,cpp}`) is lifecycle only — SoupServer, GMainContext, io thread — and composes the per-feature route modules (#440): `preview_routes` (the MJPEG endpoints `/api/preview.jpg`/`/api/preview.mjpeg`, #382, owning the client tracking and the frame-watcher thread), `subtitle_routes` (`PUT /api/subtitles/<title>` upload #212; `GET /api/subtitles/<title>` answers the stored SRT as `{"body":...}`; `DELETE /api/subtitles/<title>` removes the entry, detaching live and clearing the `active` marker when the attached one goes away, #453; `GET /api/subtitles` list and `GET`/`PUT /api/subtitle-state` #441 — the PUT takes its changes as query params, which libsoup hands the handler already parsed; `GET`/`PUT /api/subtitle-sync`, the one-shot auto-sync session, #433), `font_routes` (`GET /api/fonts` lists the renderer-available font families, #159), `whisper_routes` (`GET`/`PUT /api/whisper` toggles the tap and selects the model live, #19; `PUT /api/whisper/models/<name>` stores a downloaded ggml file into `<state-dir>/models`, temp file + rename, 512 MiB cap), `opensubtitles_routes` (`GET /api/opensubtitles` answers the `--api-key` value as JSON), and `static_files` (the `/` fallback for unmatched routes: allowlist `.html`/`.js`/`.mjs`/`.css`/`.png` — the allowlist is the MIME map; `/` maps to `index.html`, traversal and non-GET are 404). Hand-rolled JSON response helpers (`JsonEscape`/`RespondJson`/`RespondStringList`) are shared in `json_helpers`. Dependencies arrive as a `WebServerHooks` struct of std::functions filled by main.cpp (an unset hook disables its endpoints). The route headers forward-declare the GLib/libsoup types so includers (main.cpp, tests) don't need the libsoup include path. The server reads the shared preview frame buffer and toggles the preview gate via the activation hook; it must not depend on `stream/` or Gst.
- `web/` holds the static web assets served by the fallback (#212) — the future #15 UI; today `index.html` (subtitle library as a radio list that activates on change, a fuzzy filter input above the list — VSCode-style subsequence match over the stored file name, so title text and the `tt<id>` tag are the same check —, a now/next cue display that parses the attached SRT client-side — `parseCues` in `web/modules/SRT.mjs` — and tracks the extrapolated position against it (clicking the upcoming cue seeks to its start), dark theme in `assets/style.css`). OpenSubtitles search filters `languages=en` and ranks page 1 client-side by a Bayesian average of the candidate rating (fixed prior: 5 votes at 7/10, `download_count` breaks ties, #451). Uploads are named `<movie name>.os<subtitle-id>[.<fps>fps].tt<imdb-id>.srt`, and the download is skipped when the library already carries that IMDb id (client-side check via the list endpoint; the server stays title-agnostic). The Try next button (#452) walks the ranked candidates past a frontier (#453): the furthest-ranked `os` version tag the library carries is the tombstone — everything at or before it counts as tried, so deleting bad downloads behind it (per-row delete button, `DELETE /api/subtitles/<title>`) never re-fetches them, and deleting everything for a title starts over; legacy uploads predate tagging and cost one re-download. Installed to `<prefix>/share/subtitler/web`; resolved at runtime as the first `<data-dir>/subtitler/web` across `$XDG_DATA_HOME`/`$XDG_DATA_DIRS`, or via `--web-root=<dir>` in development and tests.
- `src/utils/` is a header-only INTERFACE lib `utils` (alias `subtitler::utils`) with shared utilities: `logging.h` (structured opt-in logging: `SUBTITLER_LOG="label:level,..."` parsed once into a `LogConfig`; the catch-all label `all` covers every label without its own entry. The `SUBTITLER_LOG(name, level, fmt, ...)` macro formats with `std::format` only when enabled, and per-directory label macros `CONFIG_LOG`/`MAIN_LOG`/`STREAM_LOG`/`SYNC_LOG`/`WEB_LOG` are defined there for all compilation units. Levels error/warn/info/debug; off by default. Fatal errors are **not** logged — they stay `std::println`), `reset_guard.h` (`ResetGuard`), `unique_ptr.h` (`FunctionDeleter`/`UniquePtr`, RAII for C APIs that release via a free function), `preview_frame.h` (`PreviewFrameBuffer`, the shared latest-JPEG buffer between the stream and web modules), and `paths.h` (XDG state-dir and web-root data-dir resolution, the sharded subtitle library — entries stored as `subtitles/<bucket>/<title>` with the bucket = the title's first letter lowercased or `_`, `StoreSubtitle`, `ListSubtitles`/`FindLibrarySubtitle`/`LoadLibrarySubtitle`/`RemoveLibrarySubtitle` (on-demand scans tolerating legacy flat names, #441/#453), `LibrarySubtitleTitle` (lexical path→title derivation), `SetActiveSubtitle`/`ClearActiveSubtitle`, and `active`-marker subtitle resume, #212/#438; the whisper model store `models/` — flat ggml `.bin` names, `WhisperModelNameValid`/`WhisperModelPath`/`ListWhisperModels`, #19). Utils must stay dependency-free — no Gst, no other modules. Anything Gst-dependent belongs in `stream/` (e.g. `deleters.h`); anything used by only one module stays local to that module.
- `src/stream/stream.{h,cpp}` holds the `Stream` class (pimpl): it owns the capture/output pipelines, the worker threads (video capture, audio capture, and output; audio runs only when the audio branch is enabled), and the `FrameBuffer`s (one video, one audio). Pipeline description strings are free functions in the same files (tested by `tests/description_tests.cpp`); the capture pipeline description composes separate video and audio branch descriptions. `main.cpp` is only argument parsing, signal handling, and the poll loop; the loop exits when `Stream::Failed()` goes true (#447 — capture/output bus deaths and worker-thread failures fold into it), so the process dies non-zero and the service manager restarts the appliance. When capture dies (EOS/error), `Stream::Poll` tears the capture pipeline down and the capture-side thread switches to feeding pink no-signal frames — the output side just renders whatever the frame buffer contains. `RestartCapture`/`RestartOutput` are restart-safe entry points reserved for the future web UI; nothing restarts automatically, so there are no restart loops.
- `src/stream/` also has `frame_buffer.*` (the app-owned frame queue between the threads), `drop_gate.*` (the pad-probe buffer-dropping gate for tee branches — the MJPEG preview branch, #379, and the whisper tap, #19), `whisper_transcriber.*` (windowed whisper.cpp inference fed by the audio tee; real impl under `SUBTITLER_ENABLE_WHISPER`, a stub that fails `Create` otherwise, so the rest of the stream lib needs no ifdefs — `kWhisperAvailable` is the compile-time check), and `deleters.h`.
- `src/sync/` builds the static lib `sync` (alias `subtitler::sync`): the subtitle auto-sync matching, decoupled from the stream and from whisper — `srt_cues.*` (tolerant SRT parsing for sync matching), `sync_session.*` (the one-shot session state machine and the `SyncMatcher` seam, #18/#433; text arrives as `TimestampedText`, a timestamped piece of text), and `sync_matcher.*` (the production trigram matcher, #21/#290). No Gst; consumed by `src/stream/`, which feeds it transcriber output and applies the result.
- `tests/` holds the doctest unit tests. Libs expose nothing publicly, so test targets set their own `target_include_directories` for `src/`.
- `docs/` holds appliance documentation (`docs/pi-setup.md` is the verified Pi 5 + CV105 hardware profile, `docs/video-output.md` the output/preview design, `docs/rest-api.md` the REST API reference, `docs/whisper-spike.md` the #19 spike record). The README stays the how-to; docs/ is the record — don't duplicate commands between them.
- `tools/` holds development/measurement utilities (`generate-sync-test-video.sh`, the #133 flash-and-click clip generator; `lorem-ipsum.srt`, 100 filler cues over ~10 minutes for trying the #212 upload endpoint and subtitle rendering). Not part of the build.
- `cmake/CompilerCache.cmake` sets `CMAKE_C_COMPILER_LAUNCHER`/`CMAKE_CXX_COMPILER_LAUNCHER` to buildcache when `find_program` finds one (an explicitly set launcher always wins), so the FetchContent'd whisper.cpp/ggml builds — C included — are cached too. Machines without buildcache build unwrapped.
- `cmake/CompilerWarnings.cmake` defines the `subtitler_warnings` INTERFACE target (`-Wall -Wextra -Wpedantic`), linked privately by the `stream`, `web`, and `config` libraries. The executables and test binaries still set the same flags directly on their targets.
- `cmake/Sanitizers.cmake` holds the optional sanitizers: `SUBTITLER_ENABLE_ASAN` / `SUBTITLER_ENABLE_UBSAN` (both default OFF), applied directory-scope so tests are instrumented too. Build them via the `asan-ubsan` configure/build/test presets (binary dir `build/asan-ubsan`).
- `cmake/Dependencies.cmake` declares all the pkg-config dependencies (GLib, GStreamer, libdrm, ALSA, libsoup, pangocairo) plus Threads, which nothing links yet — intentional.
- Wrap GStreamer objects with the RAII deleters in `src/stream/deleters.h` (see the `GstPointer` aliases used throughout `src/stream/stream.cpp`) instead of raw `gst_*_unref` calls. Non-owning references (GObject casts, transfer-none getters) use `GstView<T>` — never wrap those in an owning `GstPointer`; the double-unref this causes was #134.
- Installation covers the `subtitler` and `subtitler-probe` binaries (`install(TARGETS ...)` + GNUInstallDirs in the root CMakeLists), the `web/` assets (`install(DIRECTORY web ...)` to `${CMAKE_INSTALL_DATADIR}/subtitler`), the example configuration (`config/subtitler.example.ini` to the same data dir), and the systemd unit (`config/subtitler.service` to a literal `lib/systemd/system` — GNUInstallDirs' `CMAKE_INSTALL_LIBDIR` carries the Debian multiarch triplet, which units don't belong under). The `deb` target (defined only when `dpkg-buildpackage` is on PATH — the Pi, not the Arch dev machine) wraps `dpkg-buildpackage -us -uc -b`; the .deb lands next to the source dir, and the package build runs the tests and needs network for the whisper.cpp clone. `debian/` is debhelper machinery: the unit reaches the package through the CMake install rules (dh_installsystemd enables+starts it), `debian/subtitler.sysusers` creates the service user with its video/render/audio groups.

## Gotchas

- Resolution/format constants (1080p60 YUY2) and the CV105 audio constants (ALSA device `hw:CARD=Video,DEV=0`, S16LE/48kHz/stereo) live once in `src/stream/stream.cpp`; `src/probe/pipeline.cpp` keeps its own copies of the video ones for its standalone negotiation checks. They may move to the config file once that exists.
- The KMS output pipelines hardcode `kmssink driver-name=vc4` (Raspberry Pi). Output mode is selected with `--output=software|pisp|window|null` (`OutputMode` in `src/stream/stream.h`); the `kms` modes need a real V4L2 capture device and a KMS display — don't use them as a smoke test on a dev machine; build-only verification is the norm. `window` (glimagesink) and `null` (fakesink) are the dev-machine modes; `--no-audio` drops the CV105 audio branch for machines without it. The `pisp` mode is currently blocked upstream — pispconvert renders NV12 output blue on BCM2712C1 (raspberrypi/libpisp#76, see docs/pi-setup.md); `software` is the default.
- No vc4 plane supports packed 4:2:2 (no YUYV/UYVY/YVYU/VYUY — verified via `modetest -p`), so captured YUY2 frames **cannot be scanned out directly**: a conversion step (e.g. YUY2→NV16) before kmssink is mandatory. The empirical gst-launch confirmation pair is still pending; hardware profile in `docs/pi-setup.md`.
- Capture and output share one timeline (#437): `ConfigureTimeline` pins the system clock (still load-bearing — without it the pipeline adopts the alsasink ring-buffer clock, which starts at zero when the device starts, #128) and sets a common base time with start-time management left to the application, so captured PTS are valid output timestamps and capture restarts stay monotonic. Buffers are pushed with their capture PTS plus the `--audio-offset` counter-stream delay; there is no re-anchoring (the old `OutputAnchor` discarded the capture-timestamp A/V relationship — the unprincipled ~150 ms skew that needed `--audio-offset=-150`). Latency is **not** pinned: GStreamer computes it automatically, `PollBus` drains the bus and calls `gst_bin_recalculate_latency` on `GST_MESSAGE_LATENCY`, the output appsrcs report the capture-side latency hidden behind the appsink/appsrc boundary via `min-latency`/`max-latency`, and the alsasink runs a small ring buffer (`buffer-time=40000` µs — a default alsasink reports ~200 ms, which no low latency target can honor). In-flight buffering is time-sized (appsrc `max-time` 300 ms) so the render schedule can't starve the sources — that starvation was why latency was pinned in the first place (#128). The screensaver timestamps in the shared running time, capture teardown flushes both frame buffers, and the first buffer after a flush carries `DISCONT`. The `--audio-offset` trim for the remaining physical offsets (CV105 internal differential, TV audio path) measured **zero** on hardware — real-content playback has no perceptible lag at the default 0 (#437 stage 3, verified on Pi 5 + CV105); the #133 flash-and-click tooling remains for quantitative checks.
- Usage: `subtitler [video-device] [connector-id] [--config=<path>] [--output=software|pisp|window|null] [--no-audio] [--audio-output-device=<alsa-device>] [--audio-offset=<ms>] [--subtitles=<srt-file>] [--web] [--web-root=<dir>] [--api-key=<key>] [--whisper=<ggml-model>]` (`--audio-offset` shifts audio relative to video: positive delays audio, negative advances it — realized as a PTS shift on the counter-stream so no render deadline falls before buffer arrival; the #130 sync knob, now the trim for measured physical delay, #437). Defaults: `/dev/video0`, auto connector, software NV16 output, CV105 audio capture on, vc4-hdmi audio output auto-detected as the first openable vc4hdmi port via `plughw:` — raw `hw:` can't work, the MAI DAI accepts only IEC958 subframes, see docs/pi-setup.md). `--web` starts the web server on port 8080 and builds the MJPEG preview branch. `--whisper=<path>` (needs the audio branch) enables the whisper tap with that ggml model for the run, overriding the persisted `[whisper] enabled`/`model` state.
- MJPEG web preview (#376, design in docs/video-output.md): the output appsrc feeds a tee where the subtitle overlay will sit; the preview branch is `queue(leaky=1) ! videoscale 640x360 ! jpegenc ! appsink`, gated by a pad probe (`InstallDropGate`) that drops all buffers while no web client is connected and keeps every 6th frame (60→10 fps) while active. Non-obvious, all regression-tested in `tests/output_pipeline_tests.cpp`: a `valve` can't gate the branch (it fails serialized queries while dropping, stalling pipeline-wide latency computation); the preview appsink needs `async=false` (a starving gated branch would otherwise hold the whole pipeline in preroll, HDMI included — the output pipeline isn't live in the preroll sense); every tee branch needs its own queue (the HDMI one non-leaky, sized 1); and `videorate` is unusable here (it anchors its cadence to the segment start and emits a catch-up burst after every gated gap). Encoding runs only while an MJPEG client is connected; `preview.jpg`/`preview.mjpeg` serve a magenta placeholder when nothing has been encoded yet (seeded at startup, same BT.601 values as the no-signal screen).
- SRT subtitles (#438): when a path is configured, the output pipeline gains `subtitleoverlay` (which auto-plugs a textoverlay renderer) between `output_source` and the tee, plus a subtitle branch `filesrc name=subtitle_source ! application/x-subtitle ! subparse name=subtitle_parser ! subtitle_overlay.subtitle_sink`. subparse is plugged **explicitly** because subtitleoverlay's parser autoplugging can't be relied on to match it, and the named parser is where the anchor lives: cue time t renders at `anchor + delay + t` via `gst_pad_set_offset` on the parser's src pad (anchor = output running time at `StartOutput`, delay = the trim from `Stream::SetSubtitleDelay`). The offset reaches only cues parsed **after** the change (subparse consumes the whole SRT at startup), so position primitives (#439: `SubtitleTime`/`SetSubtitleTime`/`SetSubtitlesPaused`/`SubtitlesPaused`, ms) and the delay trim work by re-anchoring and flush-seeking `subtitle_source` back to the start — subparse re-emits every cue through the new offset. Pause hides the subtitles (`silent`) and freezes the position value; resume re-parses from the frozen position. An output (re)start replays from position 0 and drops any pause. Pixel-checked by the `output pipeline subtitle branch`/`reparse`/`pause and resume` tests. `Stream::SetSubtitleFile` switches or detaches the SRT through the restart-safe output rebuild (capture never restarts); `SetSubtitlesVisible` is the live `silent` toggle, re-applied across output rebuilds. SRTs live in `$XDG_STATE_HOME/subtitler/` (library in `subtitles/<bucket>/` sharded by the title's first letter, `_` for non-letters, #212; an `active` marker for boot resume). Cue font family, size, and color are live controls (#159): stored as one atomic snapshot, composed into a Pango font-desc plus the renderer's ARGB `color`, and applied to the overlay's auto-plugged text renderer — its GstChildProxy child named `renderer`, which appears only once video flows, so the stored font is applied live, on `child-added`, and across output rebuilds. `src/stream/fonts.cpp` enumerates the renderable families via pangocairo's font map. Rendering needs fonts installed — pango silently composites nothing without them (docs/pi-setup.md). The tee comment above is now historical: the tee sits right after the overlay, so the MJPEG preview shows composited subtitles.
- Whisper tap (#19): whenever the audio branch is built and whisper is compiled in, the capture pipeline carries `tee name=whisper_tee` feeding a gated second branch — leaky queue (2 s) → audioconvert/audioresample → 16 kHz mono F32LE → dropping appsink — drained by a worker thread into a `WhisperTranscriber` (5 s windows, English, 2 threads, encoder context sized to the window). The tap is toggled live, never by rebuilding: `Stream::SetWhisperState(enabled, model-path)` swaps the transcriber (an `atomic<shared_ptr>` the whisper thread copies per window) and flips the branch's `DropGate`; a present-but-disabled tap costs only the tee and queue. Models are ggml files in `<state-dir>/models/`, selected and downloaded (browser-side from HuggingFace, CORS-checked) through the web API (`GET`/`PUT /api/whisper`, `PUT /api/whisper/models/<name>`; `[whisper] enabled`/`model` persist in the config, `--whisper=<path>` overrides for a run) — never auto-downloaded. Transcripts log at `stream:info` ("Whisper heard: ..."), per-window inference time at `stream:debug`. **Every capture-tee branch needs its own queue**, same as the output tee: without one the two sinks' preroll waits serialize through the tee and deadlock the live source's PLAYING transition; and the gated branch's appsink needs `async=false`, same as the preview branch — a starving gated sink would otherwise hold the whole pipeline in PAUSED, passthrough included (both regression-tested in `tests/integration_tests.cpp`; gst-launch masks the stalls with its stream-start force-PLAYING workaround, so it is not a valid oracle for either). Lag is bounded by the leaky queue plus the dropping appsink, never by inference time; joining the whisper thread on teardown can take one window's inference (whisper_full has no cancellation point).
- One-shot auto-sync (#433): `PUT /api/subtitle-sync` starts a session (needs subtitles attached and whisper running; 202, or 409 with the reason), `GET /api/subtitle-sync` answers idle/listening/synced(time)/failed(reason). The whisper thread feeds `TimestampedText` windows (timestamp = last buffer's PTS+duration in the shared timeline) into a `SyncSession` (both from `src/sync/`) — pure bookkeeping guarded by `sync_mutex_`, which is always taken **after** `mutex_`/`whisper_mutex_`, never before; the whisper thread must not take `mutex_` (StopCapturePipeline joins it while holding `mutex_`, so that would deadlock), which is why a lock's position is applied by `Poll` (`ApplySubtitleTimeLocked`), not in the feed. `MatchTranscript` (the `SyncMatcher` seam, #18) normalizes cues and transcripts to word streams (#290), votes per window on a word offset by trigram hits (threshold + 2x margin, so repeated common phrases can't win, #21), and locks only when ≥3 windows cluster within 2 s — fail loudly, never lock wrong. The deadline (45 s) rides the shared timeline and is also enforced by `Poll`, so whisper toggles and capture loss can't strand a session; a subtitle switch, manual seek, whisper disable, or capture stop cancels it.
